# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

CS171 lab: an interactive D3 dashboard of every mapping health outcomes by state. Currently just the SvelteKit scaffold (minimal template, JavaScript, no TypeScript, no tests, no linter) plus the data in `static/`. The default `src/routes/+page.svelte` is still the placeholder.

## Commands

- `npm run dev` — dev server at http://localhost:5174/
- `npm run build` / `npm run preview` — production build / serve it

There is no test or lint script.

## Stack notes

- SvelteKit 3 (runs on Vite) + Svelte 5 with **runes mode forced** for all non-`node_modules` files (`vite.config.js`) — use `$state`/`$derived`/`$props`, not legacy `let`/`export let` reactivity or `$:`.
- `d3` v7 is the visualization library, used for scales, axes, CSV loading, and brush behavior. Svelte renders data marks with `{#each}`. D3 may manage axis and brush elements only inside dedicated `<g>` elements.
- Import `src/lib` via the `#lib` / `#lib/*` aliases (package.json `imports`), not `$lib`.
- `adapter-auto` is configured; swap it if a specific deploy target is chosen.
- `jsconfig.json` has `strict: true` and extends `$app/tsconfig` (generated by `svelte-kit sync`, run by `npm install`'s `prepare`).

## Coordination rules

- Keep `state` and `hoveredGenre` in shared state in the page. Each has one owner.
- Filtering: `let state = $state(null)`; `let filtered = $derived(...)`.  `Chain` receives `filtered` through data props.
- `Map` receives the full dataset and keeps its full year domain for hovering.
- All filtered result views must read the same derived subset.
- Filtering = remove non-matches and recompute aggregates. Say which one a feature is.

## Git workflow

- After checking each working feature, remind the user to `git add -A && git commit`.
- Prefer small, single-purpose commits with clear messages.
- If a change breaks an interaction, inspect `git diff`. If restoring a version, explain what will be discarded and let the user save any work they want to keep first.

## Data (`static/`)

`prenatal_visits_maternal_complications_bystate.xlsx` (255 rows, 14 columns, one row per state per year 2020-2024) is served at `/prenatal_visits_maternal_complications_bystate.xlsx`, so load it client-side with `d3.csv` in `onMount`. `static/prenatal_visits_maternal_complications_bystate.xlsx` has a data dictionary and notes in separate tabs; read them before charting. Only ~8 columns are intended for use: year, state, pct_maternal_morbidity, policy_rank, infant_deaths, preterm_pct, pct_zero_prenatal_visits. Narrow the dataset to these.


## Definition of done

- `npm run dev` runs with no console errors, including during interaction.
- Two views: 'Map" and 'Chain', one hover filter.
- Filtered views recompute over the subset; clearing restores all songs.
